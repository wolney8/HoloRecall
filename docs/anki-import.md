# Anki import compatibility

HoloRecall imports learning content from an `.apkg` locally. It never replaces the local collection and does not adopt Anki scheduling, review history, deck-option presets, FSRS parameters, difficulty, mastery, AnkiWeb information or reward state. Preview chooses a HoloRecall Study preset; genuinely new cards enter native New state, and reimport keeps their HoloRecall scheduler/history/cosmetics and learner management state. A lazy Web Worker runs the shared converter, then the result passes through the ordinary preview and atomic content-import transaction. Cancel is available only during analysis; after Apply begins, the atomic commit either succeeds or reports failure.

**AnkiWeb Sync is NOT PLANNED.** HoloRecall converts supported package content into its own learning model; it does not connect to an AnkiWeb account, mirror scheduler state or implement Anki's sync protocol. A possible future HoloRecall-owned cross-device service is a separate architecture decision. Exporting back to `.apkg` is also separate and is not part of this milestone; HoloRecall portable deck exchange and full learner backup remain supported.

This matrix follows Anki's official guidance for [packaged decks](https://docs.ankiweb.net/importing/packaged-decks.html), [media references](https://docs.ankiweb.net/media.html) and [field/template substitution](https://docs.ankiweb.net/templates/fields.html).

The preview reports mutually exclusive normal, simplified, excluded and unsafe card counts. Details retain per-card counts and separate reference occurrences. Informational simplifications do not require an exclusion acknowledgement; only cards that cannot be safely converted do. The importer selects the database named by detected package metadata rather than a compatibility placeholder. Unknown metadata/schema variants fail visibly. This is not universal Anki template support, native text-to-speech, Anki export, AnkiWeb sync, review-history migration or a lossless Anki round trip.

## Mapping and identity

The preview reports source-note and generated-card counts separately. Reusable mapping presets use `anki-model-v1-…`, a deterministic hash over cloze type, ordered field names and ordered template names/content. A later package with the exact signature gets the saved suggestion; a changed source schema is marked for review. Suggestions use semantic field names and unambiguous template references, never ordinal position. Metadata-like language/locale fields are ignored unless deliberately mapped. Saved mappings must resolve to fields used by a supported normal or reversed template pair. Changing a mapping previews stable existing card identities, so applying updates can preserve local edits according to the selected conflict policy without resetting history or rerolling authored rarity.

Anki `::` paths are converted once into explicit stable parent/child deck relationships; the UI never reconstructs them from punctuation. Parent Study gathers eligible descendants, child Study remains branch-scoped and reimport reuses the same source identities. HoloRecall portable format v6 preserves deck parents, card sibling groups, deck covers and inert Anki source/conversion provenance.

## Source update and conversion repair

An imported deck exposes **Update from Anki package**. It opens the file picker immediately, then a focused lazy route for that known deck rather than the general exchange page. The replacement package is analysed by stable source deck, note GUID and template/card ordinal rather than filename. Preview distinguishes new, changed, media-changed, unchanged, locally conflicting, source-removed and simplified/unsupported content, and shows representative structured Before/After values before Apply. Applying supported changes uses the existing atomic content-import transaction and preserves HoloRecall review events, FSRS state/due dates, Study preset, Focus history and earned cosmetics.

Source change and conversion change are independent. Each linked imported card retains stable collection/note/template identity, a source-content fingerprint, the accepted derived-content hash, exact mapping signature, converter/mapping/normaliser versions, an independent mapping-policy version and accepted hashes/origins for each derived field. These are versioned data contracts rather than git revisions. The preview therefore reports **Source changed** separately from **Conversion repairs**, including the case `0 source changes · N conversion repairs`.

Raw Anki notes are intentionally not retained in normal HoloRecall storage. **Repair imported content** therefore asks for the original `.apkg`, validates the selected deck identity, reruns the current bounded Worker converter and previews structured Before/After values. Repair is a distinct intent: it ignores obsolete auto-inferred mappings, reruns current semantic/template inference and shows source-field samples with its proposed mapping. A user-confirmed mapping remains authoritative. Schema-6 mappings have unknowable historical authorship, so schema 7 marks them `legacy-unclassified` and blocks Apply until the learner reviews the mapping rather than guessing. Analysis returns the exact effective mappings that produced its cards; Apply saves only that mapping/content pair. It updates existing card IDs in place and never deletes/reimports learner records. Review events, FSRS state, due dates, presets, Focus activity, rewards, hierarchy and media identity remain intact.

Local edit protection uses a field-level three-way comparison between the last accepted derived baseline, current local field and newly converted field. Converter-derived corruption remains replaceable even when an older conversion wrote that corrupt value into the accepted baseline. Card editing, bulk deck/tag changes and tag rename explicitly mark affected imported fields local. A local-only change stays local. A source-only or converter-only change updates safely. If both changed differently, the preview exposes the exact conflicting fields and defaults to **Keep local**; **Use repaired source** is explicit. Imports without trustworthy per-field provenance require review. A source-removed card remains a recoverable archive candidate rather than being deleted. Detaching a card keeps its source metadata as an inert tombstone so later packages cannot silently relink it.

Structured conversion removes `FrontSide` from the native answer and maps reliably identified prompt, answer, pronunciation, meaning and note fields separately. Multiple note fields remain separate paragraphs. Collection inspection renders the card once and places extended source notes behind disclosure. The converter preserves block/list/table boundaries without inserting global spaces between intentionally adjacent inline text.

The styling policy hashes the stable note GUID plus template/cloze ordinal, then proposes Common 55%, Uncommon 20%, Rare 12%, Holo Rare 7%, Ultra Rare 4%, Secret Rare 1%, Relic 1%. Actual counts appear before import. This is authored presentation only and never unlocks cosmetics.

## Worker, limits and security

The worker reports honest stages—archive, database, content and media—and row/file counts when known. It owns archive expansion, SQLite/WASM work, conversion and media indexing. Requests use unique IDs; repeated selection, Cancel and navigation terminate the Worker, release temporary state and ignore stale replies. A 45-second deadline fails safely. Worker startup/runtime failure never falls back to unbounded main-thread parsing.

Limits are 30 MiB compressed input, 60 MiB expanded database/archive data, 10,000 notes, 25,000 generated cards, 1,000 media items, 5 MiB per media item, 4,096 px per image side and 100,000 characters per source field. Paths, formulas/active content, malformed SQLite, oversized zstd output and missing media fail or are reported before commit. Current snapshot persistence still holds imported media in one IndexedDB state object, so very large accepted audio collections need native/media-store profiling before production scale.

Dependencies are pinned: `sql.js` 1.14.2 and `fzstd` 0.1.1 (MIT), JSZip 3.10.2 (MIT). Their runtime/WASM assets and notices are packaged locally. A production build emits a distinct lazy Anki Worker and local SQL WASM asset; heavy imports do not enter the initial route path.

## Fixture provenance and evidence

`e2e/fixtures/anki-26.9.3-legacy.apkg` and `e2e/fixtures/anki-26.9.3-modern.apkg` are review-history-free exports made with the official Anki 26.9.3 Python package. Each contains five source notes generating seven cards: Basic, reverse, two cloze deletions, image-first PNG and a custom-field card with side-specific bundled MP3. `scripts/generate-anki-fixtures.py` records the content and export settings; its development environment is excluded.

Domain checks cover both real exports, stable identity, mapping, media recovery, malformed/backup rejection and deterministic styling. Chromium and Playwright WebKit run package analysis → mapping → preview → import → explicit audio playback event → reload. A 10,000-note/card synthetic fixture (2,572,288-byte SQLite database; 249,606-byte compressed package) proves the page event loop continues ticking during analysis and Cancel leaves state byte-for-byte unchanged. Portable-format tests round-trip accents, multiline content, rarities, designs, images and audio. These browser results are not Safari, WKWebView, native iOS/macOS or physical-speaker verification.
