# Architecture

## Decision 005: background package conversion and non-enforcing capabilities

Anki package analysis runs in one lazy module Worker through a typed job protocol. The existing domain parser remains the only conversion implementation: archive inspection, bounded zstd expansion, SQLite/WASM queries, template conversion and media indexing all execute in the Worker. The UI receives named stages and completed/total counts where a real total exists; it never invents percentages. Each request has a unique ID and 45-second deadline. A new request, navigation or Cancel terminates the prior Worker, and stale replies are ignored. Worker startup/runtime failure is a safe visible failure with no main-thread parser fallback. Applying the already-previewed content remains a separate atomic IndexedDB transaction.

The packaged SQL WASM URL resolves from `document.baseURI`, so production subpaths do not depend on a development-server path. `sql.js` 1.14.2 and `fzstd` 0.1.1 remain pinned MIT dependencies with notices under `public/licenses`. The Worker is lazy, although Angular currently emits separate lazy JSZip/ExcelJS/SQLite module chunks for the main and worker dependency graphs; that duplication does not enter the initial bundle and is a future size optimization.

Schema 3 adds side-specific arrays of stable audio asset references and versioned Anki mapping presets. MP3 and WAV bytes use the same durable `asset:` identity, validation, atomic import, portable ZIP and full-backup contracts as raster media. Playback is explicit, never exposes answer audio before reveal, and stops on card changes, navigation or backgrounding. Mapping presets are keyed by a canonical signature of field names, template names/content and cloze type; a changed schema requires review. Template rows and cloze ordinals remain distinct cards, while unmapped fields stay inert metadata.

`CapabilityPolicy` is the sole application-facing product-access seam. Stable capability IDs are distinct from authored rarity, finish, earned cosmetics, scheduling and user content. The current `DevelopmentCapabilityPolicy` explicitly allows existing features and identifies itself as unverified development access; it is not evidence of purchase ownership. Import and Design Studio exercise this seam without adding a paywall or restriction. Future adapters must define verified ownership, account linking, restore, refund/revocation and offline behavior before any commercial enforcement. Learning backup/export remains available independently and contains no entitlement proof.

## Decision 004: cross-platform seams without premature native scaffolding

Every meaningful change now considers both the web application and a future Capacitor iOS runtime; the maintained evidence and native gaps live in `docs/ios-readiness.md`. Browser-engine testing is not native verification.

The current stable Capacitor line is version 8. Its documented baseline is Node 22+, Xcode 26+ and iOS 15; Swift Package Manager is the default native dependency manager. HoloRecall's Node 24.3.0 is compatible, but Capacitor packages and an `ios/` project will be added only with an authorized native build checkpoint. Capacitor 9 is prerelease and is not selected. No minimum iOS version is silently changed by this decision.

Keep the browser prototype on the validated IndexedDB snapshot adapter. Capacitor documents WebView IndexedDB on iOS as evictable and Preferences as suitable only for small values, so the native storage proposal is a versioned SQLite-backed structured store plus Filesystem-backed media, preserving the same validation, migration, compare-and-swap and backup contracts. Plugin/provider selection requires an implementation-time licence, maintenance and recovery review. Local native storage remains distinct from future authenticated cloud sync.

Use narrow platform ports for application lifecycle and generated-file delivery. Domain scheduling, reward eligibility, reports, deck schemas and XLSX/ZIP generation must remain platform-neutral. Browser delivery uses a bounded object URL; a future native implementation must write to a controlled temporary/cache file and invoke the Files/share sheet with cancellation and URI cleanup. No fake native success implementation is permitted.

The web implementation now uses `StudyPersistence`, `AppLifecycle` and `FileDelivery` boundaries. IndexedDB remains the only implemented persistence adapter; browser download remains the only implemented delivery adapter. Raster validation accepts the same bounded bytes through ImageBitmap or an Image decode fallback, while portable records continue to store stable asset IDs.

References: [Capacitor environment setup](https://capacitorjs.com/docs/getting-started/environment-setup), [storage guidance](https://capacitorjs.com/docs/guides/storage), [App lifecycle API](https://capacitorjs.com/docs/apis/app), [Filesystem](https://capacitorjs.com/docs/apis/filesystem), [Share](https://capacitorjs.com/docs/apis/share).

## Decision 002: reusable presentation and portable content

The second local milestone uses Angular Material/CDK 21.2.14, compatible with Angular 21.2.24, through the public `mat.theme` M3 API. Shared system tokens style the custom card and layout; locally bundled Roboto replaces serif UI headings. Light, Dark and System preferences apply before app startup and persist locally. [Material theming](https://material.angular.dev/guide/theming), [custom components](https://material.angular.dev/guide/theming-your-components).

Migrate schema 1 to schema 2 inside the existing IndexedDB database, retaining the exact legacy snapshot. Reusable design sets and durable raster assets are separate from card content and per-learner scheduling. Frames use a 2:3 portrait guide and protected readable areas. Uploaded code, CSS, HTML and SVG are not supported. The application owns animation behavior.

Authored rarity uses seven tiers. Earned cosmetics use auditable contributions from ratings 4/5 on scheduled reviews on distinct study days with a minimum elapsed spacing; they do not change FSRS. Unlocks survive subsequent forgetting. Undo reverses the associated contribution. Imported content never imports learning history or grants rewards.

ExcelJS 4.4.0 and JSZip 3.10.2 implement versioned, literal-value workbook and portable raster-media ZIP exchange. They load on demand. Formula cells and embedded worksheet images are rejected, and imports are previewed before a single atomic apply. Learning-progress backups remain separate. [ExcelJS](https://github.com/exceljs/exceljs), [JSZip](https://stuk.github.io/jszip/documentation/api_jszip/load_async.html).

## Decision 003: persisted session results and shared card motion

Study session completion remains part of the local atomic snapshot rather than a UI-only modal. The session records its start, natural or partial end, original planned total and per-card active/recall timing; review events retain the bounded active and question-to-reveal values used by reports/results. Results are reconstructed from active review events and active reward events by session ID. This makes reload and replay read-only, preserves reward deduplication, and lets undo reopen the corrected card without deleting history.

Active time advances only while Study is visible, focused and recently interacted with, with a 60-second idle cutoff and 120-second per-card cap. Recall time is the focused active portion from question display to reveal. Result animations do not run the Study timer. Missing historical `recallMs` values remain missing and reduce the displayed sample; they are never estimated.

The shared renderer uses one face surface and two sequential Web Animations phases totaling 760 ms. It swaps semantic/content state while edge-on, avoiding mirrored text and face bleed while preserving the controlled Angular state. Reduced motion bypasses both phases. Layer order is explicit: background/illustration/text-panel surfaces, whole-face effect overlay, rarity frame, then readable text/focus content. Overlays are pointer-inert. Card tilt wraps those internal layers and never changes queue order.

Review submission owns a finite visual handoff after the atomic save: retain the rated card, play confidence acknowledgement, deal the next persisted queue item, then release the interaction lock. Backgrounding, navigation and motion-preference settlement resolve the owned sequence without replaying the review. The Study timer is paused while the transaction/presentation lock is active, so visual timing does not inflate recall or active-study metrics.

## Decision 001: a local web milestone first

Recorded 28 September 2026 as the bootstrap architecture decision. Build one strict TypeScript, standalone Angular application, with shared domain modules and persistence behind an adapter. Use Tailwind and scoped CSS. Keep the future API boundary in `api/`; no API, authentication or cloud sync is implemented for this milestone.

Pin Angular, CLI and build tooling to **21.2.24**, TypeScript to **5.9.3**, and the existing Node **24.3.0** / npm **11.4.2** toolchain. Angular 21 is supported LTS through June 2027 and supports Node 24.3.0. Angular 22 requires a newer Node patch; choosing 21 avoids changing the global machine toolchain. Recheck support before release. Exact application dependencies are in `package.json`; retain `package-lock.json` for reproducibility. [Angular compatibility](https://angular.dev/reference/versions), [Angular support schedule](https://angular.dev/reference/releases).

Use **ts-fsrs 5.4.2** behind a pure TypeScript adapter. Ratings 1, 2, 3, 4 and 5 map to Again, Hard, Good, Good and Easy. Preserve the original five-point value and scheduler/configuration version on each review. Inject review time; disable fuzz for deterministic tests. Due dates are model estimates. Retain the dependency's licence and required notices in its distributed package. [ts-fsrs repository and licence](https://github.com/open-spaced-repetition/ts-fsrs), [API documentation](https://open-spaced-repetition.github.io/ts-fsrs/).

Pin transitive Vite to **7.3.6**, the exact version required by Angular build 21.2.24 and within Vitest 4.1.11's supported range. This avoids npm 11.4.2's observed optional-peer resolver crash through Vite 8's devtools dependency graph without disabling peer validation or upgrading the global machine. Reassess this override with a future toolchain update. [Upstream resolver issue](https://github.com/npm/cli/issues/9787), [npm overrides](https://docs.npmjs.com/cli/v11/configuring-npm/package-json#overrides).

Use an IndexedDB snapshot store for this small local dataset. Commit content, learner state and review events together in one transaction, with version checks and unique event IDs. The current ordered queue, reveal state, completed count and active-time checkpoint are persisted alongside events. Saving a review advances its session atomically. Media uses bundled references or durable asset IDs whose raster bytes are stored in the same snapshot. Browser storage can be cleared or evicted and is not a guaranteed durable native database or a cloud backup.

The domain layer is in `src/domain`; `src/app/data` implements the IndexedDB adapter and Angular signal store. Schema version 5 is validated on load. Versions 1–4 migrate atomically, with each original snapshot retained under its migration key in the existing database. Unsupported or malformed data is reported without reset. Atomic compare-and-swap rejects stale tab writes and leaves the unsubmitted card on screen; there is no durable pending-event outbox yet. Same-tab mutations are serialized; the database compare-and-swap still protects against other tabs. JSON export/restore is described in the README and tested in domain and browser checks. The FSRS MIT notice is preserved in `docs/third-party/ts-fsrs-LICENSE.txt` and the Angular production build's `3rdpartylicenses.txt`.

## Data and scheduling boundaries

Card/deck content is separate from learner progress. Each learner/card state has a concurrency version. Review events retain their event, learner, card and session IDs; content revision; UTC timestamp; original rating; mapped FSRS grade; previous/resulting state; scheduler version; and the resolved HoloRecall preset/parameter snapshot. Normal reviews are immutable. Undo appends a reversal and updates the current state atomically. Set-due/reset/bury/suspend/reposition append separate administrative events, so reports and rewards continue to consume only active scheduled reviews.

Default day boundaries use `Europe/London`, independent of UTC storage. Stable Study presets resolve from each card's home deck, followed by direct deck and valid today-only workload overrides. Accepted review events retain the owning deck and ancestry, selected Study root, learner day and time zone so repeated sessions rebuild branch-scoped usage from persisted truth. Selecting a parent caps the combined queue while every applicable intermediate/leaf branch caps its descendant contribution; directly selecting a child stops limit resolution at that child and does not consume unrelated branches. Only cards admitted inside the selected-root cap consume branch allowance. New introductions and mature reviews have separate ledgers; learning/relearning remains scheduler-correct. Deterministic queue construction supports the documented order set, and the visual deck consumes the persisted queue without shuffling it. Practice and administrative events remain separate from scheduled reviews. Rapid submissions and duplicate event delivery must not create extra reviews or rewards.

The local prototype has one local learner. It does not establish cloud identity, remote ownership or cross-device conflict resolution. Collection samples have no effect on progress or rewards. A future learner-specific challenge policy needs minimum evidence, separate promotion/recovery thresholds and an explanation; cosmetic unlocks are a separate system.


## Local implementation details

### Decision 004: bounded local Anki conversion and versioned finishes

Anki deck packages are converted locally into the validated HoloRecall content model, then applied through the existing atomic content-import boundary. The parser selects the database from package metadata, lazy-loads pinned `sql.js` 1.14.2 and `fzstd` 0.1.1, and never executes source HTML, CSS, JavaScript or SVG. Stable note GUID plus template/cloze ordinal identities drive reimport, sibling groups and deterministic authored rarity. New decks receive the preview-selected HoloRecall Study preset; reimport preserves native scheduler/history/rewards and learner management state. Anki scheduling, options, history, parameters and AnkiWeb data remain outside conversion. HoloRecall will not implement AnkiWeb sync; future HoloRecall-owned sync is separate. The exact verified and pending variants live in `docs/anki-import.md`.

Content exchange format v2 adds card finish overrides and reusable design finish/layout/texture fields while retaining version-1 import compatibility. Finish presets remain app-owned declarative behavior over the renderer layers; user uploads remain bounded raster data. Rarity, finish, design, unlock state and FSRS state are separate fields and responsibilities.

- **Material 3:** `src/theme.scss` uses the supported `mat.theme` and `mat.theme-overrides` APIs, a generated forest-green tonal palette, Roboto and density 0. Custom components consume `--mat-sys-*` color, shape and typography roles. No private Material component selectors are overridden. The early theme script applies the cached preference before styles paint; IndexedDB remains authoritative. System uses CSS `color-scheme`/`light-dark` and follows device changes.
- **Presentation:** the renderer keeps background, illustration, frame and effect layers separate. Protected text areas are opaque; decoration ignores input. Pointer/drag transforms wrap the card, and reveal/deal effects do not mutate scheduler order. Intersection/visibility observers and reduced motion control animation. No Lottie asset or Jitter service is required.
- **Page entrances:** `ViewportRevealService` owns reusable viewport observation and one observer per scrolling root. The standalone `hrReveal` directive applies the shared 460 ms / 10 px settle tokens to meaningful wrappers, settles on focus, reduced motion, disabled effects or backgrounding, and cleans up on removal. Results reuses the visibility service but retains its run-specific balances, Skip/Replay and timers. Card transforms, Study controls, expansion transitions and urgent status/error content are explicit exclusions.
- **Cosmetics:** immutable contribution events reference their review and study date/time zone. Ratings 4/5 qualify once per distinct study day and at least 20 elapsed hours apart. Thresholds for the seven ordered tiers default to 1/2/3/5/8/12/20 and must strictly increase. Unlock events retain the contributing IDs and threshold at earning time. Undo appends reward reversals; later low ratings do not revoke earned cosmetics. Changing thresholds applies on future qualifying reviews, with no retroactive grant. Old reviews are never replayed for rewards.
- **Reports:** scheduled review counts and confidence use active (not reversed) events. Recall success is ratings 2–5 / all scheduled reviews in the selected calendar period. Attention means at least two rating-1 outcomes among the last five reviews in that period. Inventory/due counts and FSRS mean retrievability are current, outside the event date filter. Active time counts focused visible study with interaction in the preceding 60 seconds, capped at 120 seconds per card; legacy events have no invented timing. Practice is excluded and reported separately, but no practice UI is implemented.
- **Storage/media:** schema 2 adds declarative design sets, raster assets, reward events/configuration and current session. Interactive upload accepts decoded PNG/WebP/JPEG up to 4 MB and 16–4096 px per side. Replacement uploads get new IDs; existing referenced bytes are not overwritten. Unused uploads are retained until a future safe garbage-collection feature. Full backups embed uploaded bytes; content ZIPs bundle them. The original trusted SVGs remain code-native project assets, never executable user uploads.
- **Bundle/dependencies:** secondary screens are deferred; ExcelJS, JSZip and the Anki parser load only when exchange is used. Their tested CommonJS distributions are explicitly allowed. The unchanged initial warning ceiling is 850 kB; the current Study checkpoint measures 852.98 kB, a 2.98 kB warning recorded as HR-PERF-01 rather than hidden by raising the budget. ExcelJS, SQLite WASM and Anki conversion remain lazy chunks. ExcelJS's `uuid` dependency is overridden to pinned 11.1.1 (its used `v4` CommonJS API is compatible) to remove the older vulnerable dependency chain. PostCSS 8.5.28 and Vitest 4.1.11 are pinned. Build extraction retains dependency notices; Roboto OFL and exchange/import library notices also ship under `public/licenses`. Recheck budgets and overrides with the next bounded route/chunk change.

## Preserved cloud direction

- **Web/API:** Vercel-hosted built web assets plus a small TypeScript API. Server-only code and database credentials stay outside browser and native bundles. Check current Vercel limits and configuration before deployment.
- **Database:** Neon PostgreSQL through the API, with migrations, foreign keys, ownership constraints, unique event IDs and due-queue indexes. Do not add an overlapping database service without a recorded decision. Preserve study history during schema changes.
- **Identity:** Auth0 is proposed, not selected through implementation. Validate the current Angular/Capacitor SDK compatibility, Google/Apple setup and service limits before commitment. The server must validate credentials and derive learner identity from them, then check resource ownership.
- **Native identity:** Plan separate browser/native callbacks, authorization code with PKCE where appropriate, verified deep links, logout and suitable token storage. Browser success does not verify native login. [Auth0 Angular/Capacitor guide](https://auth0.com/docs/quickstart/native/ionic-angular).
- **Media:** Object storage holds bytes; PostgreSQL holds owned metadata and references. Select an adapter/provider and document current costs, limits, upload validation, size restrictions and deletion behaviour before enabling cloud uploads. Bundled assets need no external account.
- **Sync:** Define a durable outbox, unique event IDs, acknowledgements, retries and visible pending/error states. The server validates submitted events and calculates resulting scheduling/rewards; it must not trust client-supplied XP or final state. Detect stale state versions, retain pending work and surface conflicts. Define resolution and clock-skew handling before claiming multi-device offline sync.
- **Portability:** A versioned JSON export/restore contract must include content, review history, scheduling/configuration state and packaged media or resolvable references. Validate imports and avoid silent replacement. Add CSV validation/duplicate handling later; Anki `.apkg` support needs an explicit supported subset. No AnkiWeb sync is promised.

## Decision 006: reconstructable local index and payload media registry

Schema 4 adds explicit deck parents plus non-destructive deck/card archive state. Parent study includes descendants; suspension or archive on any ancestor excludes that branch from scheduled queues and ordinary library results. Tags are canonicalised for casing, accents and spacing while preserving a stable display label. Bulk content changes commit once and do not alter scheduling, review or reward records.

The learner-facing search document is a reconstructable read model, never portable user data. Collections above 500 cards build it in a lazy local Worker; smaller collections avoid Worker startup overhead. Queries operate on normalized indexed fields and return 60-item visible slices so foil cards and media are not mounted for the whole collection. Lifecycle backgrounding cancels the Worker, stale results are ignored, and a missing Worker produces a visible safe error for large data rather than blocking the main thread.

IndexedDB version 2 keeps validated state metadata in `local-study` and media payloads in `local-media` under stable content-hash keys in the same transaction. Imports and restores recompute SHA-256 from the bytes before storage identity or deduplication is trusted. Reference accounting covers card images/audio and design backgrounds/frames/textures; cleanup is explicit and refuses referenced assets. Routine state commits retain unchanged media keys without hydrating or rewriting their bytes. The application still hydrates assets on initial web load, so a future native adapter and further very-large-media profiling remain required.

Deck content exchange format v4 carries explicit `parentId` hierarchy and `siblingGroupId` content relationships; v1–v3 remain readable without guessing missing hierarchy from titles. Archive state, learner settings, reviews and creation metadata remain full-backup concerns rather than deck-content exchange fields.

## Native feasibility

Capacitor remains the iOS direction. Current stable Capacitor **8.5.2** requires Node 22+, full **Xcode 26+**, and supports **iOS 15+**. Swift Package Manager is the default native dependency manager; CocoaPods is optional. [Environment setup](https://capacitorjs.com/docs/getting-started/environment-setup), [iOS requirements](https://capacitorjs.com/docs/ios).

The environment check found Command Line Tools but no working full Xcode installation. No native build or physical-device test has run. Keep the native feasibility build as the next iOS task when Xcode is available; it does not block this local web milestone. Packaged iOS must contain built web assets, use the hosted API and never depend on a development-server URL.

Device motion remains opt-in future work, with user-triggered permission, denial/absence handling and inactive-listener cleanup. Native authentication, lifecycle/storage and motion require real-device evidence. CSS effects come first; WebGL requires measured benefit and device profiling. No microservices, Nx, Kubernetes, GraphQL or large state framework is currently justified.
