# Anki import compatibility

HoloRecall treats an `.apkg` as a content source. The primary conversion path is:

```text
Anki deck + note type + note + card template
→ safe template rendering
→ native HoloRecall question and answer
→ optional semantic enrichment
→ HoloRecall Study preset and five-confidence FSRS workflow
```

This follows Anki's documented model: note fields are arbitrary, templates determine the generated cards and their front/back content, and a note may generate several cards. See the official [template introduction](https://docs.ankiweb.net/templates/intro.html), [field replacements](https://docs.ankiweb.net/templates/fields.html), [card generation](https://docs.ankiweb.net/templates/generation.html), and [packaged decks](https://docs.ankiweb.net/importing/packaged-decks.html).

HoloRecall does not import Anki scheduling, review history, due dates, deck-option presets, FSRS parameters, difficulty, mastery, AnkiWeb account data, or reward state. New cards enter native New state under the selected HoloRecall Study preset. Updates and conversion repairs retain the existing HoloRecall card ID, review events, FSRS state, due date, preset, Focus history, authored presentation, and earned cosmetics.

**AnkiWeb Sync is NOT PLANNED.** HoloRecall is not an AnkiWeb client. Future HoloRecall-owned sync remains a separate architecture decision.

## Template-first compatibility

The safe compatibility engine is a non-executing interpreter. It currently handles:

- ordinary `{{Field}}` replacements and static template text;
- nested positive and inverse field conditionals;
- `{{FrontSide}}` and `<hr id="answer">` answer boundaries;
- Basic, reversed, optional-reversed rows already generated by Anki, and ordinary cloze deletions;
- `text:` and `cloze:` filters;
- answer-input, TTS, hint, furigana, kana, and kanji filters as explicit safe simplifications;
- `Tags`, `Type`, `Deck`, `Subdeck`, and `Card` special fields;
- local image and `[sound:...]` references, including side-specific MP3/WAV audio.

The engine never executes JavaScript, event handlers, `javascript:` URLs, arbitrary executable template code, imported CSS, or active SVG. Remote media, scripts, and fonts are not fetched. Unknown filters, malformed conditionals, unavailable template ordinals, and cards with no usable prompt/answer become compatibility review or unsupported results rather than entering Study corrupted.

Anki templates determine learning content. HoloRecall continues to determine card presentation, including its renderer, design sets, finishes, rarity, motion, and accessibility behavior. Arbitrary downloaded CSS is not copied into the product shell.

For ordinary cards, the engine derives the primary answer from the answer-side template structure: an explicit answer region such as the source `.italian` block or content after `<hr id="answer">` is authoritative. It never selects the first referenced field as a general rule. A one-field back can keep safely rendered static text around that field; cloze and static-only backs use the complete safe result. `FrontSide` is removed from native answer content so the prompt is not duplicated.

## Source-native snapshot

State schema 8 retains a compact inert source snapshot after successful import. It is separate from learner state and contains:

- source deck identities, paths, and explicit parent relationships;
- note-type identity/name, cloze type, ordered field definitions, canonical schema signature, and ordered card templates;
- note identity/GUID, raw inert values keyed by source field name, tags, and source modification time when present;
- source card identity, note reference, template identity/ordinal, and owning source deck;
- source media aliases pointing to shared durable assets;
- a versioned content fingerprint.

The `.apkg` archive and its database are not stored wholesale. Media bytes live once in the shared content-addressed registry and snapshot references count during safe cleanup. Full learning backups include schema-8 snapshots and validate their card/media references. Current XLSX/portable content exchange carries the usable native cards and per-card inert provenance, but not the full source snapshot; package-free reconversion after moving a deck to another installation therefore requires a full backup. This portability limitation remains explicit rather than silently expanding the public deck format.

Cards retain their Anki note GUID plus template ordinal identity for compatibility with existing imports, alongside the normalized source snapshot and template IDs. Source fingerprints use note GUID, model signature, template content/ordinal, ordered source values, tags, deck identity, and referenced media. Filename and displayed answer are never identity.

## Semantic enrichment

Once a template has produced a safe question and answer, HoloRecall may populate Pronunciation, Meaning, Notes, Language metadata, examples, and side-specific media from conservative name/template evidence or a saved user-confirmed enrichment mapping. Enrichment failure never replaces or blocks a valid template answer. Unmapped fields remain inert in the source snapshot instead of being concatenated into Notes.

Advanced field enrichment is collapsed by default. It uses one compact row per source field with sample values and a destination. It appears automatically only when a card genuinely needs compatibility review, or when the learner explicitly opens it to enrich native fields. Historical automatic mappings do not override template-rendered question/answer content. Explicit user mappings can rescue an otherwise unsupported template when they provide a complete safe front and answer, but they still cannot replace a valid template-derived answer.

## Semantic interoperability and Mapping Studio

HoloRecall uses one versioned, subject-neutral semantic role contract for projection review. Recall roles are situation/context, primary prompt, task guidance, hint, choices and instructional artwork. Answer essentials are primary answer, secondary cue, concise example and concise interpretation. Support roles are explanation, rule/pattern, method, worked steps, reference table, usage/examples, memory aid, source/reference, additional detail and the safe original-details fallback. Media, decorative, duplicate-FrontSide, hidden and ignored roles are presentation classifications rather than learning content.

Analysis creates a Mapping Profile for each stable note-type and card-template identity. Each source field retains its destination, confidence and evidence. Confirmed exact-template profiles outrank confirmed model profiles and automatic inference; a later automatic analysis cannot silently replace a learner-confirmed profile. Automatic inference uses template-side references and conservative semantic evidence after template rendering, so optional mapping never decides whether an otherwise valid card has a front or answer.

New imports include an **Import Review** with representative Recall, Answer and Answer Support previews. High-confidence packages remain a short Review → Import flow. **Review semantic mapping** opens the lazy Mapping Studio only on request or when meaningful content needs review. Its compact source/sample/role rows update the same import preview and can be reset to current automatic inference. The default mapping scope is the exact note type + card template and therefore applies to every matching card rather than one card at a time. Existing imported decks expose the same action under Manage Anki source; Apply reprojects the retained snapshot in place through the ordinary atomic transaction, preserving IDs and every learner/cosmetic state.

Standard cloze deletions in generated source cards remain supported within the documented filter subset. Advanced add-on cloze behavior remains a safe simplification or review result. Image Occlusion note types are detected and retained but require a dedicated mask/occlusion projector; they are not claimed as faithfully supported and cannot silently degrade into ordinary cards.

## HoloRecall to Anki export contract

Two versioned profiles are available as a preview and Anki-compatible UTF-8 text export:

- **HoloRecall Basic** emits Front and Back. Selecting it for a rich card shows an explicit loss warning.
- **HoloRecall Extended v1** emits stable Identity and Deck plus Prompt, Context, Guidance, Hint, Choices, Answer, Secondary, Example, Interpretation, Support, Media, Source and Tags. Blank optional fields are valid. Its predictable templates use conditional sections and an explicit `{{FrontSide}}<hr id="answer">` boundary.

The file includes documented Anki text-import headers for separator, HTML, note type, deck, tags and columns. It is an interoperable intermediate, not an `.apkg`. Production APKG database/media creation remains `HR-ANKI-EXPORT-APKG-01`; HoloRecall will not emit an undocumented SQLite archive merely to claim package support. Imported cards derive export identity from source model/note/template identity. Native cards use their stable HoloRecall card ID, so repeated exports have deterministic identities. Source provenance remains authoritative for later Anki package updates; export does not detach or rewrite it.

## Compatibility tiers

| Tier | UI label | Meaning |
| --- | --- | --- |
| A | Ready | Template semantics, question/answer, and supported media convert normally. |
| B | Ready with simplifications | Core card is usable; optional Anki behavior or presentation is omitted. |
| C | Needs review | A safe question/answer requires an explicit compatibility decision. |
| D | Unsupported | No safe usable card can be produced; explicit exclusion is required. |

Tier A/B cards import automatically. Optional enrichment uncertainty is not Tier C.

## Import, update, and repair

Ordinary import is **choose package → analyse → concise compatibility summary → Import**. Supported packages do not expose field mapping. Analysis runs in the existing lazy Worker, reports notes/cards/decks/media and A–D counts, and remains cancellable before Apply.

An imported deck exposes **Update from Anki package**. This opens the file picker for that known source, compares stable identities, shows new/source-changed/conversion-repair/media/unchanged/conflict/source-removed counts, and applies through the atomic content transaction. Missing source cards are retained as recoverable archive candidates; updates never delete learning history.

**Repair imported content** is distinct from source update. For schema-8 imports it renders the retained snapshot with the same structured conversion service used by fresh import and package update, so an unchanged package is not needed. Legacy imports without a snapshot ask for the matching package once, create the snapshot, then preview an in-place repair. Converter, enrichment and normalizer versions are independent from the source fingerprint. Existing corrupted converter-derived values can be replaced; fields proven locally edited stay local by default.

Analysis creates one version-bound transaction plan for every affected card: current value, template-derived proposal, field provenance/conflicts and final selected value. The Before/After UI renders that plan, and Apply commits its selected payload rather than recomputing or rebinding from the current card. A concurrent local version/source change invalidates the plan and requires reanalysis. Accepted importer-baseline equality identifies legacy converter-derived content even when an obsolete origin flag is misleading; actual editor-origin changes remain local by default. Content repair never treats presentation-only art/rarity/finish differences as content conflicts.

The structured projection keeps the principal template answer in `answer`, dedicated pronunciation and Meaning/English fields in their native properties, and labelled Literal, Usage/examples, SoundNote/pattern and Sources/reference values in content-v7 `details`. Local `notes` remain separate. Study shows the concise answer fields with extended details disclosed; inspection/editor expose all details; management rows remain bounded.

Apply commits cards, decks, durable assets, exact enrichment mappings, and the normalized source snapshot in one optimistic transaction. It never writes scheduler/history/reward state.

## Front and back semantic fidelity

The safe template projection applies a coverage contract to both faces. Every meaningful rendered source block is classified or retained; optional semantic enrichment may improve placement, but it cannot make source content disappear.

On Recall, the subject-neutral presentation model separates `situationContext`, `primaryPrompt`, `taskGuidance`, `hint`, choices and instructional artwork. A material situation remains visible when a Question/Focus is also present. For example, the retained Lesson 1 note `26af5d2f4845d6d5` renders Prompt `A formal interaction with an unfamiliar adult`, Focus `Which “you”?`, and Task `Say it in Italian`; all three are represented, while the target `Lei` remains absent until reveal.

On Answer, `FrontSide` is classified as duplicate Recall content rather than repeated. An explicit `<hr id="answer">` establishes the ordinary answer boundary, but unlabelled/internal `<hr>` elements remain structural evidence and are never a universal split algorithm. Primary answer, optional secondary cue and a genuinely concise interpretation remain on the collectible face. Other meaningful content becomes labelled Answer Support outside the card. Safe headings, paragraphs, lists, tables and code/preformatted blocks use an inert declarative model; scripts, handlers, active SVG, remote execution and source CSS remain excluded. Meaningful safe content that cannot be classified without guessing is retained once under collapsed **Original card details**.

Imported cards retain block-level provenance sufficient to trace source field/block → classification → Recall, Answer or support destination. This is internal evidence, not learner-facing Study chrome. Repair and update derive this projection from the retained source snapshot and preserve explicit local presentation overrides plus all learner state.

## Structured Answer Support contract

Safe source structure remains declarative after import. Headings, paragraphs, lists, tables, code/preformatted content and term/description or key/value pairs have distinct block types; table-cell line breaks stay associated with their row and column. The Study renderer may recover those blocks from a retained normalized source snapshot when an older native projection stored only a flattened `CardDetail.content`. Recovery matches the accepted source-derived text, executes no source behavior and does not mutate the card, accepted baseline or learner state. If no source structure can be matched safely, the content remains one inert readable paragraph rather than being guessed into language-specific columns.

Answer Support is outside the collectible card and belongs to the whole revealed Study stage. Small useful sections render directly; longer reference sections may use progressive disclosure. Wide tables scroll within their own region and cannot widen the page.

## Language recall presentation

Template-first import remains authoritative for the question, answer and source snapshot. A separate language presentation projection may promote retained `Question`, `Focus`, `Context`, `Task`, `Hint` and English/Meaning fields into a clearer recall hierarchy when an imported front is only a vague instruction. It never changes the template-derived target answer. `Complete the phrase` is usable only with a visible incomplete phrase; an illustration instruction retains image-first treatment only when the source intentionally made the image the retrieval cue. Otherwise Auto selects the text-first collectible composition.

Artwork role and Study-art preference are local presentation metadata. An Anki update may improve derived defaults but cannot silently overwrite an explicit user override; hiding art never detaches or deletes imported media. Existing imported cards can resolve presentation from their retained snapshot without reimporting or altering learning state.
