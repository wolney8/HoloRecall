# Architecture

## Decision 011: local-first identity, verified capabilities and commercial seams

HoloRecall remains usable as an anonymous local application. UI and learning domain code depend on a provider-neutral `AuthSession`; the current `LocalAuthSession` proves no remote identity and owns no learning data. A future authenticated account uses a stable HoloRecall account UUID and maps verified `(issuer, subject)` identities separately. Signing out removes credentials and remote session state but never deletes local cards, reviews, FSRS state, cosmetics or recovery exports.

**Recommended future provider: Auth0**, subject to a separately approved credential/backend milestone. It has maintained Angular PKCE, Capacitor/Ionic and native Sign in with Apple guidance, Google/social support and server-side JWT validation. HoloRecall's future API must verify issuer, signature, audience, expiry and scopes before mapping identity; secrets and refresh credentials never enter Angular bundles or learner backups. Neon remains the proposed application database rather than being replaced by the identity provider. Account linking requires proof of both identities, and account creation must include export, reauthentication, provider-token revocation and cloud-account deletion design.

`CapabilityPolicy` remains the only product-access decision seam. Identity, learning data, cosmetic progress, verified product entitlement and advertising policy are independent. Development allow-all access is explicitly unverified. A future entitlement adapter may aggregate verified Apple purchase and web-account ownership, including restore/refund/revocation/offline states, without altering study history or granting cosmetics. The purchase model remains undecided.

`AdPolicy` is a central default-off boundary. Study, Practice, ratings, Session Complete, cosmetic unlock, import/export and destructive confirmation are structurally ineligible for ads. No advertising SDK, placement, tracking, consent flow or empty ad container exists. Any future SDK requires product approval plus Apple privacy/ATT, age/child treatment, web consent and platform permission review. Apple digital feature unlocks must follow applicable App Store purchase rules.

References: [Auth0 Angular SDK](https://auth0.com/docs/libraries/auth0-angular-spa), [Auth0 Ionic/Capacitor](https://auth0.com/docs/quickstart/native/ionic-angular), [native Sign in with Apple](https://auth0.com/docs/authenticate/identity-providers/social-identity-providers/apple-native), [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/), [account deletion/token revocation](https://developer.apple.com/documentation/technotes/tn3194-handling-account-deletions-and-revoking-tokens-for-sign-in-with-apple), and [privacy/ATT](https://developer.apple.com/app-store/user-privacy-and-data-use/).

## Decision 005: background package conversion and non-enforcing capabilities

Anki package analysis runs in one lazy module Worker through a typed job protocol. The existing domain parser remains the only conversion implementation: archive inspection, bounded zstd expansion, SQLite/WASM queries, template conversion and media indexing all execute in the Worker. The UI receives named stages and completed/total counts where a real total exists; it never invents percentages. Each request has a unique ID and 45-second deadline. A new request, navigation or Cancel terminates the prior Worker, and stale replies are ignored. Worker startup/runtime failure is a safe visible failure with no main-thread parser fallback. Applying the already-previewed content remains a separate atomic IndexedDB transaction.

The packaged SQL WASM URL resolves from `document.baseURI`, so production subpaths do not depend on a development-server path. `sql.js` 1.14.2 and `fzstd` 0.1.1 remain pinned MIT dependencies with notices under `public/licenses`. The Worker is lazy, although Angular currently emits separate lazy JSZip/ExcelJS/SQLite module chunks for the main and worker dependency graphs; that duplication does not enter the initial bundle and is a future size optimization.

Schema 3 adds side-specific arrays of stable audio asset references and versioned Anki mapping presets. MP3 and WAV bytes use the same durable `asset:` identity, validation, atomic import, portable ZIP and full-backup contracts as raster media. Playback is explicit, never exposes answer audio before reveal, and stops on card changes, navigation or backgrounding. Mapping presets are keyed by a canonical signature of field names, template names/content and cloze type; a changed schema requires review. Template rows and cloze ordinals remain distinct cards, while unmapped fields stay inert metadata.

`CapabilityPolicy` is the sole application-facing product-access seam. Stable capability IDs are distinct from authored rarity, finish, earned cosmetics, scheduling and user content. The current `DevelopmentCapabilityPolicy` explicitly allows existing features and identifies itself as unverified development access; it is not evidence of purchase ownership. Import and Design Studio exercise this seam without adding a paywall or restriction. Future adapters must define verified ownership, account linking, restore, refund/revocation and offline behavior before any commercial enforcement. Learning backup/export remains available independently and contains no entitlement proof.

## Decision 004: cross-platform seams without premature native scaffolding

Every meaningful change considers Web, iOS/iPadOS, Android and the iOS/iPad application on Apple-silicon Mac; the maintained evidence and native gaps live in `docs/ios-readiness.md`. Browser-engine testing is not native verification, emulator evidence is not physical-device evidence, and Intel Mac is not planned.

The project pins Capacitor core/CLI/iOS/Android **8.5.2**, App **8.1.2**, Filesystem **8.1.4**, Haptics **8.0.2** and Share **8.0.3**. Capacitor 8's documented baseline is Node 22+, Xcode 26+ and iOS 15; its generated Android project uses minSdk 24, compile/target SDK 36, AGP 8.13.0, Gradle 8.14.3 and Java 21. HoloRecall's Node 24.3.0 is compatible. Both generated shells consume `dist/holorecall/browser` without a development-server URL. Xcode 26.6 with iOS 26.5 now provides iPhone/iPad Simulator compilation and runtime evidence. Android Studio/JDK/SDK remain absent and Android native verification is deferred by current product priority. Capacitor 9 prerelease is not selected.

Keep the browser prototype on the validated IndexedDB snapshot adapter. Capacitor documents WebView IndexedDB on iOS as evictable and Preferences as suitable only for small values, so the native storage proposal is a versioned SQLite-backed structured store plus Filesystem-backed media, preserving the same validation, migration, compare-and-swap and backup contracts. Plugin/provider selection requires an implementation-time licence, maintenance and recovery review. Local native storage remains distinct from future authenticated cloud sync.

Use narrow platform ports for application lifecycle and generated-file delivery. Domain scheduling, reward eligibility, reports, deck schemas and XLSX/ZIP generation must remain platform-neutral. Browser delivery uses a bounded object URL; a future native implementation must write to a controlled temporary/cache file and invoke the Files/share sheet with cancellation and URI cleanup. No fake native success implementation is permitted.

The web implementation uses `StudyPersistence`, `AppLifecycle` and `FileDelivery` boundaries. `StudyPersistence` is injectable, with IndexedDB still the only production provider. Browser download remains the web delivery adapter; the native path lazily writes generated bytes to Cache and invokes the official Share surface. Capacitor App lifecycle events also load lazily into the shared lifecycle boundary. Raster validation accepts the same bounded bytes through ImageBitmap or an Image decode fallback, while portable records continue to store stable asset IDs.

`InteractionFeedback` is the semantic tactile boundary. Study calls reveal, accepted-rating, deal, completion, genuine-unlock and real-error cues only after the authoritative action succeeds. Its native adapter lazy-loads official Capacitor Haptics; web is a strict no-op, lifecycle/background and the persisted Haptics preference suppress calls, and native failures never delay or fail learning. Android Back is isolated in the native navigation adapter. Product version comes from `package.json`; `scripts/sync-native-version.mjs` copies it into iOS `MARKETING_VERSION` and Android `versionName`, while platform build numbers remain monotonic native metadata.

Normal delivery remains a future release activity: Xcode archive, TestFlight and App Store for iOS/iPadOS; Gradle Android App Bundle, Play internal testing and Google Play for Android; and the compatible iPhone/iPad application on Apple-silicon Mac after Mac-specific acceptance. Capacitor is the maintained shared native runtime, not a reason to fork the Angular/domain product or scatter platform branches through scheduling. No signing, store record or secret belongs in the web bundle or repository.

References: [Capacitor environment setup](https://capacitorjs.com/docs/getting-started/environment-setup), [storage guidance](https://capacitorjs.com/docs/guides/storage), [App lifecycle API](https://capacitorjs.com/docs/apis/app), [Filesystem](https://capacitorjs.com/docs/apis/filesystem), [Share](https://capacitorjs.com/docs/apis/share).

Uploaded code, CSS, HTML and SVG are not supported. The application owns animation behavior.

## Decision 003: persisted session results and shared card motion

Study session completion remains part of the local atomic snapshot rather than a UI-only modal. The session records its start, natural or partial end, original planned total and per-card active/recall timing; review events retain the bounded active and question-to-reveal values used by reports/results. Results are reconstructed from active review events and active reward events by session ID. This makes reload and replay read-only, preserves reward deduplication, and lets undo reopen the corrected card without deleting history.

Active time advances only while Study is visible, focused and recently interacted with, with a 60-second idle cutoff and 120-second per-card cap. Recall time is the focused active portion from question display to reveal. Result animations do not run the Study timer. Missing historical `recallMs` values remain missing and reduce the displayed sample; they are never estimated.

The shared renderer uses one face surface and two sequential Web Animations phases totaling 760 ms. It swaps semantic/content state while edge-on, avoiding mirrored text and face bleed while preserving the controlled Angular state. Reduced motion bypasses both phases. Layer order is explicit: background/illustration/text-panel surfaces, whole-face effect overlay, rarity frame, then readable text/focus content. Overlays are pointer-inert. Card tilt wraps those internal layers and never changes queue order.

Review submission owns a finite visual handoff after the atomic save: retain the rated card, play confidence acknowledgement, deal the next persisted queue item, then release the interaction lock. Backgrounding, navigation and motion-preference settlement resolve the owned sequence without replaying the review. The Study timer is paused while the transaction/presentation lock is active, so visual timing does not inflate recall or active-study metrics.

Recorded 28 September 2026 as the bootstrap architecture decision. Build one strict TypeScript, standalone Angular application, with shared domain modules and persistence behind an adapter. Use Tailwind and scoped CSS. Keep the future API boundary in `api/`; no API, authentication or cloud sync is implemented for this milestone.

Angular 21 is supported LTS through June 2027 and supports Node 24.3.0. Angular 22 requires a newer Node patch; choosing 21 avoids changing the global machine toolchain. Recheck support before release. Exact application dependencies are in `package.json`; retain `package-lock.json` for reproducibility. [Angular compatibility](https://angular.dev/reference/versions), [Angular support schedule](https://angular.dev/reference/releases).

Use **ts-fsrs 5.4.2** behind a pure TypeScript adapter. Ratings 1, 2, 3, 4 and 5 map to Again, Hard, Good, Good and Easy. Preserve the original five-point value and scheduler/configuration version on each review. Inject review time; disable fuzz for deterministic tests. Due dates are model estimates. Retain the dependency's licence and required notices in its distributed package. [ts-fsrs repository and licence](https://github.com/open-spaced-repetition/ts-fsrs), [API documentation](https://open-spaced-repetition.github.io/ts-fsrs/).

This avoids npm 11.4.2's observed optional-peer resolver crash through Vite 8's devtools dependency graph without disabling peer validation or upgrading the global machine. Reassess this override with a future toolchain update. [Upstream resolver issue](https://github.com/npm/cli/issues/9787), [npm overrides](https://docs.npmjs.com/cli/v11/configuring-npm/package-json#overrides).

Use an IndexedDB snapshot store for this small local dataset. Commit content, learner state and review events together in one transaction, with version checks and unique event IDs. The current ordered queue, reveal state, completed count and active-time checkpoint are persisted alongside events. Saving a review advances its session atomically. Media uses bundled references or durable asset IDs whose raster bytes are stored in the same snapshot. Browser storage can be cleared or evicted and is not a guaranteed durable native database or a cloud backup.

The domain layer is in `src/domain`; `src/app/data` implements the IndexedDB adapter and Angular signal store. Schema version 6 is validated on load. Versions 1–5 migrate atomically, with each original snapshot retained under its migration key in the existing database. Unsupported or malformed data is reported without reset. Atomic compare-and-swap rejects stale tab writes and leaves the unsubmitted card on screen; there is no durable pending-event outbox yet. Same-tab mutations are serialized; the database compare-and-swap still protects against other tabs. JSON export/restore is described in the README and tested in domain and browser checks. The FSRS MIT notice is preserved in `docs/third-party/ts-fsrs-LICENSE.txt` and the Angular production build's `3rdpartylicenses.txt`.

## Data and scheduling boundaries

Card/deck content is separate from learner progress. Each learner/card state has a concurrency version. Review events retain their event, learner, card and session IDs; content revision; UTC timestamp; original rating; mapped FSRS grade; previous/resulting state; scheduler version; and the resolved HoloRecall preset/parameter snapshot. Normal reviews are immutable. Undo appends a reversal and updates the current state atomically. Set-due/reset/bury/suspend/reposition append separate administrative events, so reports and rewards continue to consume only active scheduled reviews. New administrative operations share a bulk group ID and exact affected before/after projections; undo first validates the entire group against current state and then appends immutable reversal records atomically. Snapshot-free legacy events remain readable and non-undoable.

Default day boundaries use `Europe/London`, independent of UTC storage. Stable Study presets resolve from each card's home deck, followed by direct deck and valid today-only workload overrides. Accepted review events retain the owning deck and ancestry, selected Study root, learner day and time zone so repeated sessions rebuild branch-scoped usage from persisted truth. Selecting a parent caps the combined queue while every applicable intermediate/leaf branch caps its descendant contribution; directly selecting a child stops limit resolution at that child and does not consume unrelated branches. Only cards admitted inside the selected-root cap consume branch allowance. New introductions and mature reviews have separate ledgers; learning/relearning remains scheduler-correct. Deterministic queue construction supports the documented order set, and the visual deck consumes the persisted queue without shuffling it. Practice and administrative events remain separate from scheduled reviews. Rapid submissions and duplicate event delivery must not create extra reviews or rewards.

Auto Advance is a presentation policy on the shared player, not a scheduling operation. A generation-, session- and card-bound finite timer may reveal a question after the configured delay. It pauses for inactive lifecycle state and active media, persists interruption as paused with bounded remaining time, and requires deliberate resume after recovery. It never supplies a rating. Accepted ratings persist before the existing confidence/deal choreography, and optional answer timing only sets a minimum revealed-card dwell before the next card. Those presentation delays occur after captured recall/active time and do not change FSRS, Practice boundaries or rewards.

Easy Days is evaluated but not implemented. `ts-fsrs` 5.4.2 provides fuzzing and rescheduling, but no weekday workload-distribution input equivalent to current Anki. HoloRecall will not hide due work or rewrite the returned due date with a separate calendar heuristic; implementation waits for a scheduler-supported integration that preserves interval/state semantics.

The local prototype has one local learner. It does not establish cloud identity, remote ownership or cross-device conflict resolution. Collection samples have no effect on progress or rewards. A future learner-specific challenge policy needs minimum evidence, separate promotion/recovery thresholds and an explanation; cosmetic unlocks are a separate system.


## Local implementation details

### Decision 004: template-first Anki compatibility

**Status: accepted architecture; mapping-first conversion is legacy.** Anki note fields are arbitrary, so a field-name/position mapping cannot be the authority for card validity. HoloRecall now retains a compact source-native representation of source decks, note types, ordered fields, templates, notes, generated cards and media aliases. A safe non-executing template interpreter derives each question and answer from the source card template; optional semantic enrichment then populates pronunciation, meaning, notes and media metadata. Enrichment uncertainty never replaces or blocks a valid template answer.

The interpreter supports the documented ordinary field, static text, nested conditional, `FrontSide`, answer-boundary, text, cloze, reverse, TTS/typed-answer simplification and standard special-field subset. JavaScript, event attributes, active SVG, remote dependencies, unknown executable filters and imported CSS remain outside the trust boundary. Templates determine content while the shared HoloRecall renderer determines presentation. Compatibility is explicitly classified A (ready), B (safe simplification), C (manual compatibility review) or D (unsupported); only C opens mapping automatically.

The exact Italian Lessons acceptance package also establishes a declarative presentation boundary: source Picture markup is parsed into stable source-panel data, visible Options labels become native inert choice chips, and optional Answer labels/details remain separate fields. Angular bindings render that model; raw source HTML, CSS and event handlers never enter the application DOM. Format v7 carries this declarative art/choice/detail data through portable content exchange while the full backup retains the normalized source snapshot.

State schema 8 stores the normalized inert snapshot separately from learner data and maps its media aliases to the shared registry. It does not retain the raw archive/database. Existing GUID-plus-template-ordinal card IDs remain stable, and source snapshot/template IDs plus source fingerprints support package updates and future re-rendering. Direct package analysis and retained-snapshot repair call one structured conversion service; converter/enrichment/template/normalizer versions can invalidate derived content without pretending the source changed. A version-bound transaction plan carries each current, proposed and final-selected card plus field conflicts from Preview through Apply. Optimistic state checks reject stale plans, and accepted field baselines distinguish legacy converter output from actual local edits. The atomic import transaction commits source snapshot, native cards/decks/media and exact optional enrichment mappings together. Repair can re-render schema-8 imports without the package; a pre-schema-8 import supplies the package once to bootstrap the snapshot. Anki scheduling/options/history/parameters and AnkiWeb data remain outside conversion; AnkiWeb Sync is NOT PLANNED. Detailed tiers and format coverage live in `docs/anki-import.md`.

Content exchange format v2 adds card finish overrides and reusable design finish/layout/texture fields while retaining version-1 import compatibility. Finish presets remain app-owned declarative behavior over the renderer layers; user uploads remain bounded raster data. Rarity, finish, design, unlock state and FSRS state are separate fields and responsibilities.

- **Material 3:** `src/theme.scss` uses the supported `mat.theme` and `mat.theme-overrides` APIs, a generated forest-green tonal palette, Roboto and density 0. Custom components consume `--mat-sys-*` color, shape and typography roles. No private Material component selectors are overridden. The early theme script applies the cached preference before styles paint; IndexedDB remains authoritative. System uses CSS `color-scheme`/`light-dark` and follows device changes.
- **Presentation:** the renderer keeps background, illustration, frame and effect layers separate. Protected text areas are opaque; decoration ignores input. Pointer/drag transforms wrap the card, and reveal/deal effects do not mutate scheduler order. Intersection/visibility observers and reduced motion control animation. No Lottie asset or Jitter service is required.
- **Page entrances:** `ViewportRevealService` owns reusable viewport observation and one observer per scrolling root. The standalone `hrReveal` directive applies the shared 460 ms / 10 px settle tokens to meaningful wrappers, settles on focus, reduced motion, disabled effects or backgrounding, and cleans up on removal. Results reuses the visibility service but retains its run-specific balances, Skip/Replay and timers. Card transforms, Study controls, expansion transitions and urgent status/error content are explicit exclusions.
- **Cosmetics:** immutable contribution events reference their review and study date/time zone. Ratings 4/5 qualify once per distinct study day and at least 20 elapsed hours apart. Thresholds for the seven ordered tiers default to 1/2/3/5/8/12/20 and must strictly increase. Unlock events retain the contributing IDs and threshold at earning time. Undo appends reward reversals; later low ratings do not revoke earned cosmetics. Changing thresholds applies on future qualifying reviews, with no retroactive grant. Old reviews are never replayed for rewards.
- **Reports:** scheduled review counts and confidence use active (not reversed) events. Recall success is ratings 2–5 / all scheduled reviews in the selected calendar period. Attention means at least two rating-1 outcomes among the last five reviews in that period. Inventory/due counts and FSRS mean retrievability are current, outside the event date filter. Active time counts focused visible study with interaction in the preceding 60 seconds, capped at 120 seconds per card; legacy events have no invented timing. Practice uses separate events/results and remains excluded from scheduled recall, FSRS and reward metrics.
- **Storage/media:** schema 2 adds declarative design sets, raster assets, reward events/configuration and current session. Interactive upload accepts decoded PNG/WebP/JPEG up to 4 MB and 16–4096 px per side. Replacement uploads get new IDs; existing referenced bytes are not overwritten. Unused uploads are retained until a future safe garbage-collection feature. Full backups embed uploaded bytes; content ZIPs bundle them. The original trusted SVGs remain code-native project assets, never executable user uploads.
- **Bundle/dependencies:** secondary screens are deferred; ExcelJS, JSZip, Focus query/UI and the Anki parser load only when their features are used. Their tested CommonJS distributions are explicitly allowed. HR-PERF-01 separated Appearance/Material toggle and local backup/media tools from the root shell while retaining eager Study recovery. The closure build measures **847.67 kB raw / 198.69 kB transfer**, below the unchanged 850 kB ceiling (before: 867.32 kB / 199.15 kB). Study Settings is a 23.57 kB lazy chunk; Focus, Exchange, History, ExcelJS, SQLite WASM and Anki conversion remain lazy. ExcelJS's `uuid` dependency is overridden to pinned 11.1.1 (its used `v4` CommonJS API is compatible) to remove the older vulnerable dependency chain. PostCSS 8.5.28 and Vitest 4.1.11 are pinned. Build extraction retains dependency notices; Roboto OFL and exchange/import library notices also ship under `public/licenses`.

## Preserved cloud direction

- **Web/API:** Vercel-hosted built web assets plus a small TypeScript API. Server-only code and database credentials stay outside browser and native bundles. Check current Vercel limits and configuration before deployment.
- **Database:** Neon PostgreSQL through the API, with migrations, foreign keys, ownership constraints, unique event IDs and due-queue indexes. Do not add an overlapping database service without a recorded decision. Preserve study history during schema changes.
- **Identity:** Auth0 is proposed, not selected through implementation. Validate the current Angular/Capacitor SDK compatibility, Google/Apple setup and service limits before commitment. The server must validate credentials and derive learner identity from them, then check resource ownership.
- **Native identity:** Plan separate browser/native callbacks, authorization code with PKCE where appropriate, verified deep links, logout and suitable token storage. Browser success does not verify native login. [Auth0 Angular/Capacitor guide](https://auth0.com/docs/quickstart/native/ionic-angular).
- **Media:** Object storage holds bytes; PostgreSQL holds owned metadata and references. Select an adapter/provider and document current costs, limits, upload validation, size restrictions and deletion behaviour before enabling cloud uploads. Bundled assets need no external account.
- **Sync:** Define a durable outbox, unique event IDs, acknowledgements, retries and visible pending/error states. The server validates submitted events and calculates resulting scheduling/rewards; it must not trust client-supplied XP or final state. Detect stale state versions, retain pending work and surface conflicts. Define resolution and clock-skew handling before claiming multi-device offline sync.
- **Portability:** A versioned JSON export/restore contract must include content, review history, scheduling/configuration state and packaged media or resolvable references. Validate imports and avoid silent replacement. Add CSV validation/duplicate handling later; Anki `.apkg` support needs an explicit supported subset. No AnkiWeb sync is promised.

## Decision 006: reconstructable local index and payload media registry

Schema 4 adds explicit deck parents plus non-destructive deck/card archive state. Parent study includes descendants; suspension or archive on any ancestor excludes that branch from scheduled queues and ordinary library results. Tags are canonicalised for casing, accents and spacing while preserving a stable display label. Bulk content changes commit once and do not alter scheduling, review or reward records.

The learner-facing search document is a reconstructable read model, never portable user data. Collections above 500 cards build it in a lazy local Worker; smaller collections avoid Worker startup overhead. Queries operate on normalized indexed fields and return 60-item visible slices so foil cards and media are not mounted for the whole collection. Lifecycle backgrounding cancels the Worker, stale results are ignored, and a missing Worker produces a visible safe error for large data rather than blocking the main thread.

IndexedDB version 2 keeps validated state metadata in `local-study` and media payloads in `local-media` under stable content-hash keys in the same transaction. Imports and restores recompute SHA-256 from the bytes before storage identity or deduplication is trusted. Reference accounting covers card images/audio and design backgrounds/frames/textures; cleanup is explicit and refuses referenced assets. Routine state commits retain unchanged media keys without hydrating or rewriting their bytes. The application still hydrates assets on initial web load, so a future native adapter and further very-large-media profiling remain required.

Deck content exchange format v6 carries explicit `parentId` hierarchy, `siblingGroupId` relationships, deck-cover media and per-card inert Anki provenance; v1–v5 remain readable. State schema 8 adds the normalized source snapshots required for package-free re-rendering. Full backups carry them. Current content-only XLSX/ZIP does not, so transferring package-free repair capability requires a full backup; the native cards themselves remain portable and usable. Archive state, learner settings and reviews remain full-backup concerns.

Imported source content and learner state remain separate. Update compares stable source identities/fingerprints. Repair compares the conversion contract and re-renders the retained snapshot. Optional automatic mappings may be refreshed; user-confirmed enrichment remains authoritative unless changed explicitly. Local authoring marks affected fields local while retaining accepted source baselines. Detach persists a tombstone so matching source cannot silently reattach a card. Card/deck editing and destructive branch deletion preserve scheduler/review/reward identities unless deletion is explicitly confirmed; source media participate in reference-safe cleanup.

## Decision 007: non-destructive Focused Sessions and explicit Practice events

Schema 6 gives every active session an explicit `scheduled` or `practice` mode. Scheduled Focus narrows the real due/new queue and uses the existing FSRS review writer; it cannot make an arbitrary future card due. Practice uses a separate immutable event writer that never changes scheduling state, due dates, daily limits, leech state or rewards. The scheduled writer requires a revealed active Scheduled session, so UI routing cannot accidentally turn Practice confidence into a review.

A Focus request stores versioned selection criteria, bounded order/limit and a per-run random seed. The resulting ordered card IDs are persisted for interruption recovery while cards keep their home deck/subdeck identities. Saved Focus presets store criteria rather than copied card content and reevaluate against the current library on every run. Missing, archived, ancestor-suspended or newly buried cards are pruned safely from a paused session. Full backup version 6 includes Practice events, Focus presets and active Focus state; v1–v5 remain migrated and schema-5 pseudo-practice review records retain their authoritative scheduler chain as Scheduled history.

## Decision 008: Apple native storage and first macOS route

**Status: Simulator feasibility validated; production provider and migration remain unimplemented.**

Keep the Angular application and domain model. The generated Capacitor 8 iOS/iPad shell is the native delivery baseline. Web continues to use IndexedDB. A shipped iOS build should use a transactional SQLite implementation behind `StudyPersistence` for structured state and Application Support files for content-addressed media, while keeping stable `asset:` identifiers in cards and portable data. A DEBUG-only system SQLite probe, isolated from production state, now proves Application Support persistence, transactions/rollback, relaunch, update and schema migration on iOS Simulator. No official Capacitor SQLite plugin exists. `@capacitor-community/sqlite` 8.1.1 remains unadopted because its SQLCipher/export surface and current v8 maintenance issues need resolution; an app-owned narrow Swift/Capacitor bridge over system SQLite is the preferred next implementation spike. Preferences/UserDefaults is not a learning database.

Migration is backup-first and idempotent: validate legacy data; retain and hash a recovery backup; stage structured data and media under a deterministic source fingerprint; verify collection counts, hierarchy, event identities, FSRS state, settings, rewards, Anki identities and media hashes; then atomically select the native version. Interrupted staging is discarded or resumed from its journal. IndexedDB and the recovery backup remain untouched until a later explicit confirmation. The fixture-tested orchestration contract is not a production migration and is never invoked automatically.

Recommend the same iPad-capable iOS application on Apple-silicon Macs as HoloRecall's first macOS release candidate. ## Decision 009: adaptive shared shell and Study composition

**Status: implemented and iPhone/iPad Simulator verified.**

The Angular shell adapts by available layout space rather than platform or device names. At compact widths it exposes four equal primary destinations in a safe-area-aware bottom bar (`Decks`, `Study`, `Collection`, `More`); Progress and less-frequent destinations live in the disclosed More menu. A shared route/deck context model supplies the single compact parent/title/back header and the semantic wide breadcrumb. Study and Session Complete suppress the bottom bar because they provide their own explicit exit/continuation controls. At tablet and desktop widths the persistent/collapsible rail remains authoritative.

Study keeps one shared renderer and player. Compact touch layouts use the semantic active card as the single-tap reveal control, reserve a fixed presentation envelope before and after reveal, and place five equal-width confidence targets in a safe-area-aware dock. Wider layouts retain the balanced card plus right-hand rating panel. Space or Enter reveals and keys 1–5 rate, while shortcut prose lives in contextual help rather than the permanent touch interface. Presentation callbacks remain owned by the existing generation/card identity lifecycle, so responsive changes do not alter queue order, persistence, FSRS mapping, Practice isolation or reward rules.

Imported HTML normalization preserves block/newline and table-cell boundaries while leaving intentionally adjacent inline text unchanged. Responsive styles use shared breakpoints, safe-area environment values, viewport height and reflow rules; no stored content or domain contract contains device-specific coordinates. The visual viewport coordinator scrolls only a focused editable control that falls outside the current visual viewport, covering keyboard resizing without fixed notch or keyboard dimensions.
